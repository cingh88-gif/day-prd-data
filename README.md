# day-prd-data

iERP **공정진척현황(작업보고) `PM60250Rv3`** 에서 지정 작업반의 데이터를 엑셀출력으로 받아
모으고, **진행률 보고서**를 만든다. **일마감(하루) · 월마감(한 달) · 직접 지정 기간** 을
모두 받으며, 정해진 시각에 자동으로 돈다(일마감은 매일, 월마감은 매월).

`ierp-prod-report`(일일생산실적 PM60230Uv3) · `ierp-manhour`(공수 PM40510Uv3) 와 같은 구조다.
그쪽에서 실측으로 얻은 win32 접근·Excel COM 저장·재접속 로직을 그대로 이식했다.

## 집계 규칙 (사용자 확정)

| 항목 | 정의 |
|---|---|
| 제외 | 오더상태 **30작업지시** 건 |
| 모수 | **50작업진행 + 80작업완료** |
| 일마감 진행률 | **80작업완료 ÷ 모수** |
| 건수 단위 | **작업지시번호 기준 distinct** (공정별로 여러 행이 내려와도 1건) |

> **왜 화면에서 30을 미리 안 거르나.** 조회조건으로 빼 버리면 30이 몇 건이었는지 알 수 없어,
> *수집이 덜 된 것*인지 *원래 30이 많았던 것*인지 구분이 안 된다. 그래서 **ALL 로 받아서
> 집계에서** 거르고, 제외한 건수까지 보고서에 남긴다.

## 대상 작업반 (12개)

`M2105 하이드로겔실` · `03160 세리안코스메틱` · `M2103` · `M1103` · `M2101` · `M2109` ·
`M2102` · `J2001` · `M2107` · `M1101` · `M1102` · `M1104`

GUI 에서 켜고 끄고 추가/삭제할 수 있다. 이름이 빈 작업반은 **첫 수집 때 iERP 가 돌려준
작업반명으로 자동으로 채워진다.**

## 전제

- **수집은 Windows 전용.** 집계·보고서(`aggregate.py`/`report.py`)는 WSL 에서도 돈다.
- iERP 는 **사용자가 직접 로그인**해 둔 상태 — **iEMenu** 가 떠 있어야 한다.
- iERP 와 **권한을 맞춘다.** iERP 는 보통 권한(asInvoker)이므로 이 도구도 **그냥 더블클릭**하면 된다.
  관리자 권한은 필요 없다. 시작 전에 양쪽 무결성 레벨을 비교해서(`preflight`), 이 도구가
  더 낮으면 원인을 짚어 주고 **아예 시작하지 않는다** — 형제 프로젝트에서 이 조합으로
  13개월치를 조용히 건너뛴 사고가 있었다.
- 수집 중에는 마우스/키보드를 만지지 말 것 (키 입력이 iERP 창으로 들어간다).

### 2) 실행

```
실행.bat                ← GUI. 작업반·기간·실행시각을 여기서 정한다
지금수집.bat            ← 전날치(일마감)를 바로 한 번
월마감.bat 2026-08      ← ★ 그 달 전체 (인자 없으면 전월)
집계만.bat 2026-08-31   ← 이미 받아 둔 폴더로 보고서만 다시
```

CLI 로도 된다:

```powershell
py run_daily.py                                   # 전날(일마감)
py run_daily.py --date 2026-08-31                 # 특정 하루
py run_daily.py --month 2026-08                   # ★ 그 달 전체(월마감)
py run_daily.py --last-month                      # ★ 전월 전체
py run_daily.py --from 2026-08-01 --to 2026-08-15 # 직접 기간
py run_daily.py --teams M2105,M1101               # 일부 작업반만(시험용)
py run_daily.py --no-collect --month 2026-08      # 집계·보고서만 다시
```

### 기간 모드

| 모드 | 개시예정일 | 폴더 | 파일 |
|---|---|---|---|
| 일마감 | 그날 하루 | `day_20260831_092529` | `progress_M2105_20260831_092529.xlsx` |
| **월마감** | **1일 ~ 말일** | `month_202608_143022` | `progress_M2105_202608_143022.xlsx` |
| 직접 지정 | 시작 ~ 종료 | `range_20260801-20260815_101500` | `progress_M2105_20260801-20260815_101500.xlsx` |

**이름 뒤의 숫자는 실행 시분초다.** 같은 기간을 여러 번 돌릴 수 있으므로, 실행마다
폴더와 파일이 갈려 **앞 결과를 덮어쓰지 않는다.** 결과를 나란히 두고 비교할 수 있다.

중간에 실패한 실행을 **이어서 채우려면** `--resume`(GUI 에서는 `이어받기` 체크):
그 기간의 가장 최근 폴더를 재사용하고 이미 받은 작업반은 건너뛴다.

```powershell
py run_daily.py --month 2026-08            # 새 폴더에 처음부터
py run_daily.py --month 2026-08 --resume   # 최근 폴더를 이어서 채움
```

> 모드 접두어(`day_`/`month_`/`range_`)로 갈라 두어서 '8월 하루치' 와 '8월 한 달치' 가
> 섞이지 않는다. 말일은 달력에서 구하므로 윤년도 맞다(2024-02 → 29일).
> `--no-collect`(집계만)는 그 기간의 **가장 최근 폴더**를 쓴다.

### 자동 실행

GUI 의 스케줄 칸에서 두 가지를 따로 등록한다. **작업 이름이 달라 서로 덮어쓰지 않는다.**

| | 주기 | 받는 기간 | 작업 이름 |
|---|---|---|---|
| 일마감 | 매일 `HH:MM` | 전날 하루 | `iERP_일마감_공정진척` |
| **월마감** | **매월 N일 `HH:MM`** | **전월 전체** | `iERP_월마감_공정진척` |

입력한 시각이 오전인지 오후인지 옆에 바로 표시된다(`11:00` → 오전 11:00, `23:00` → 오후 11:00).
월마감 실행일은 **1~28 일만** 받는다 — 29~31 일은 없는 달이 있어 그 달을 통째로 건너뛴다.

> **자동 실행은 PC 가 켜져 있고 로그온된 상태에서만 된다.** iERP 창을 실제로 조작해야 하므로
> `/IT`(대화형)로 등록한다. 이게 없으면 세션 0 에서 돌아 창을 못 찾고 **매일 조용히 실패**한다.

## 이 화면을 다루는 핵심 원칙 (형제 프로젝트 실측 이식)

**UIA 깊은 탐색을 절대 하지 않는다.** 그리드에 수천 행이 차면 컨트롤 하나 찾는 데:

| 방법 | 소요 |
|---|---|
| win32 `EnumChildWindows` | **0.00초** |
| UIA 깊은 탐색(`child_window`) | 63초 뒤 **실패** |

그래서 컨트롤은 ① win32 로 **찾고** ② 핸들 바인딩 UIA(`ElementFromHandle`, O(1))로
**읽고 누른다.**

**조회가 끝났는지도 그리드를 읽어서 판단하지 않는다.** 조회 중에는 앱이 메시지 펌프를
멈추므로(제목에 `(응답 없음)`), `SendMessageTimeout` 으로 **앱이 살아났는지**만 본다.

## 알려진 함정

| 함정 | 대응 |
|---|---|
| 조회가 끝나기 전 엑셀출력 → **행 수는 맞는데 전부 빈 칸** | `wait_responsive` 로 앱 응답을 기다린 뒤 출력 |
| iERP 가 시트 **크기를 먼저 잡고** 값을 나중에 채움 | `UsedRange` 크기만 보지 않고 `CountA` 까지 3회 연속 같을 때만 저장 |
| DTP 를 `DTM_SETSYSTEMTIME` 으로 바꾸면 표시만 바뀜 | 실제 키 입력 후 **읽어서 확인**. 화살표 이동은 순환이라 안 씀 |
| **작업반 입력이 안 먹은 채 조회** → 다른 작업반 데이터가 그 작업반 파일로 저장 | 코드 입력 후 **읽어서 대조**하고, 저장된 파일의 작업반 열까지 다시 대조 (`verify_saved`) |
| 엉뚱한 날짜를 그 날짜 파일로 저장 | 조회 **직전에** 화면 날짜를 한 번 더 대조 |
| 빈 파일을 남기면 재개 때 건너뜀 | 검증 실패 시 **파일을 지우고** 실패 처리 (Excel 이 놓을 때까지 재시도 삭제) |
| 매 출력마다 빈 Excel 껍데기가 쌓임 | `cleanup_excel()` — 단 **사용자 Excel 은 보호**(`guard_excel`) |
| 연달아 조회하다 화면이 죽음 | 2개 연속 실패하면 화면 재접속. 안 하면 남은 작업반이 전부 몇 초짜리 실패로 소진됨 |
| **프로그램ID 를 `PM60250R` 로 열면 안 열림** | 버전 접미사까지 — **`PM60250Rv3`**. 검색창이 남으면 `열기` 버튼 폴백 |
| **`작업완료 포함`(chkSELOPT1)이 꺼진 채로 뜬다** | 그대로 조회하면 **80작업완료가 통째로 빠져 진행률이 매일 0%** 로 나온다. 화면을 새로 열 때마다 꺼지므로 **매 실행 시작에 켜고 읽어서 확인**한다. 못 맞추면 수집을 아예 시작하지 않는다 |
| **`개시예정일` 시작 칸이 비어 있어 타이핑이 통째로 무시된다** | `CustomFormat=" "` 라 편집할 날짜 구역 자체가 없다. `DTM_SETSYSTEMTIME`(프로세스 경계 못 넘음)·Legacy SetValue·ValuePattern 전부 막혀 있었다. **▼(달력) 클릭 → Enter** 로 값을 살린 뒤에야 타이핑이 먹는다 (`materialize_dtp`) |
| **Edit 값을 `window_text()`/`GetWindowText` 로 읽으면 항상 빈 값** | 값이 멀쩡히 들어 있는데도 ''로 읽혀 "작업반이 안 들어갔다" 고 오판했다. **UIA ValuePattern → WM_GETTEXT** 순으로 읽는다 (`_edit_text`) |
| **`Excel 정리` 직후 포커스가 흔들려 작업반 입력이 사라진다** | 다음 작업반 코드가 안 들어가고 **이전 값이 남는다.** 입력 직전에 창을 다시 앞으로 가져오고, 값을 읽어 확인한 뒤 **최대 3회 재시도**한다 |
| **Excel 이 COM 호출을 거부(`RPC_E_CALL_REJECTED`)** | 사용자가 열어 둔 Excel 이 바쁘면 난다. 예외를 삼키면 "Excel 없음" 으로 5분간 조용히 기다리다 실패한다 → 짧게 재시도하고, 끝까지 거부하면 **어느 창이 거부했는지 로그에 남긴다** |
| **검색창의 '열기' 는 버튼이 아니라 콤보박스 드롭다운 화살표다** | `프로그램 실행` 창의 입력칸은 Edit 이 아니라 편집형 ComboBox 이고, UIA 가 그 드롭다운 버튼에 붙이는 이름이 하필 `열기`(15x18px)다. 그걸 누르면 목록만 펼쳐지고 **프로그램은 안 열린다.** 이 창에 확인/실행 버튼은 없다 — **제출 수단은 Enter 뿐이다** |
| **실패한 검색창을 안 닫으면 창이 쌓여 iEMenu 가 통째로 막힌다** | `프로그램 실행` 이 4개까지 쌓인 걸 봤다. 그 뒤로는 **어떤 프로그램ID 도** 안 열려서(다른 화면도) 원인이 전혀 안 보인다. 시도 전후로 남은 창을 **전부** 닫는다(하나만 닫으면 소용없다) |
| **`send_keys` 가 괄호를 먹는다** | `공정진척현황(작업보고)` 을 그냥 보내면 `공정진척현황작업보고` 가 입력된다. `^ + % ~ ( ) { } [ ]` 는 send_keys 문법 문자라 `{(}` 처럼 이스케이프해야 한다(`esc_keys`) |
| **iERP 가 매 엑셀출력마다 좀비 EXCEL.EXE 를 남긴다** | 쌓이면 `_find_export_wb` 가 좀비를 뒤지느라 느려지고, 좀비가 COM 을 거부하면 저장이 통째로 실패한다. 시작 전에 **보이는 창이 없는** EXCEL.EXE 만 정리한다(`sweep_zombie_excel`). 사용자 문서는 반드시 창이 있으므로 안전하다 |
| **`SetForegroundWindow` 가 조용히 거부돼 키가 엉뚱한 창으로 간다** | 호출 프로세스가 포그라운드가 아니면 Windows 가 거부한다(예외 없이 실패만). 그대로 `send_keys` 하면 무인 실행에서 `PM60250Rv3` 이 사용자의 메모장에 찍힌다. → AttachThreadInput → ALT 키 + TOPMOST 토글 순으로 올리고 **확인**한다. 끝내 못 올리면 **키를 보내지 않고 멈춘다**. 실제로 사용자가 열어 둔 다른 iERP 화면(`PM10105Rv1`)이 막고 있었다 |
| cp949 는 em dash(`—`)를 인코딩하지 못한다 | `.bat` 파일에 `—` 를 쓰면 그 지점에서 파일이 잘린다. 배치파일 주석에는 `-` 만 쓴다 |
| 보고서를 열어 두면 다음 실행에서 같은 이름으로 저장 불가 | 저장 전에 **그 워크북만** 닫는다(`close_workbook_at`). 그래도 안 되면 시각을 붙여 저장하고 알린다 |
